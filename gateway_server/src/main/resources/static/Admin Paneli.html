Toplam PodAktif Kullanıcı (ölçekli)

Servis durumu nasıl kontrol edilir?

  • /actuator/health her serviste 5–20sn aralıkla otomatik yoklanır.
  • kubectl get pods -n telcox ile pod durumu ve restart sayısı.
  • Grafana + Prometheus — CPU / RAM / latency metrikleri.
  • Zipkin — dağıtık trace: gecikme hangi serviste görülür.
  • Kafka UI (:9093) — consumer lag ve topic sağlığı.

Kubernetes servisleri nasıl yönetiyor?

  • HPA CPU/istek yoğunluğuna göre pod sayısını min–max aralığında otomatik ayarlar.
  • Readiness probe başarısız pod trafik almaz; liveness başarısız pod yeniden başlatılır.
  • Stabilization window ani salınımı (flapping) önler.
  • Kaynak yetersizse Cluster Autoscaler yeni node ekler.
  • Sürekli çöken pod CrashLoopBackOff'a düşer — manuel müdahale gerekir.
